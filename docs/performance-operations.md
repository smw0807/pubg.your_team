### 팀 목록

- `createdAt DESC`, 문서 ID `DESC` 순서와 문서 스냅샷 커서를 함께 사용한다. 같은 생성 시각의 팀도 페이지 사이에서 건너뛰지 않는다. 기존 인덱스의 암묵적 문서 ID 정렬과 동일한 방향이다.
- 한 번에 한 페이지의 리스너만 유지한다. 이전/다음 페이지와 최신 팀으로 돌아가기 버튼을 제공한다. 숫자는 전체 팀 수가 아닌 **현재 페이지**의 팀 수다.
- 필터 변경은 1페이지부터 시작한다. 새로고침/연결 복구는 현재 페이지를 다시 구독한다. 이전 요청의 늦은 콜백은 무시한다. 오프라인·캐시 응답·로딩/오류 상태에서는 다음 페이지로 진행하지 않는다.
- **종료된 팀의 서버 필터는 이번에 적용하지 않았다.** 기존 활성 팀에는 `closedAt` 필드가 없으므로 `closedAt == null`을 추가하면 기존 팀이 조회에서 사라진다. 상태 필드 도입은 규칙·구버전 클라이언트·기존 방 이전을 함께 처리해야 한다.
- 대신 읽어 온 최대 20개 중 종료 팀을 화면에서 제외한다. 커서는 마지막 원본 문서를 사용하므로 한 페이지가 모두 종료 팀이어도 다음 페이지로 갈 수 있다. 결과가 20개보다 적거나 비어 있을 수 있음을 안내한다. 종료 팀도 이 제한 내 읽기 비용에 포함된다.
- 실시간 목록은 새 생성/삭제로 페이지 경계가 움직일 수 있다. 페이지 번호는 고정된 전체 목록의 스냅샷 번호가 아니다. 최신 팀으로 돌아가 새 목록을 확인할 수 있다.

### 채팅

```text
room/[id].vue
├─ useChat (기존 권한·입퇴장·전송 유지)
│  └─ useChatHistory → chatHistory 서비스
│     ├─ 최근 50개 실시간 구독
│     └─ 이전 50개씩 서버 확인 조회
└─ ChatPanel → useChatScroll (이전 메시지 로딩 중 보이는 메시지 위치 유지)
```

- 최근 기록은 내림차순으로 제한 조회하고 화면에는 시간/나노초/문서 ID 오름차순으로 표시한다. 과거 조회는 `getDocsFromServer`를 사용해 일부만 있는 오프라인 캐시를 마지막 페이지로 오인하지 않는다.
- 이전 조회 중에도 최신 기록을 합치고 ID로 중복을 제거한다. 실패는 읽던 기록과 커서를 유지한 채 재시도할 수 있다. 서버 시각이 확정되지 않은 커서는 과거 조회에 사용하지 않는다.
- 방 변경·퇴장·구독 중단·컴포넌트 해제는 진행 중인 요청 결과를 무효화한다. 재연결하면 최신 구간으로 초기화했다는 안내를 표시한다.
- 서버가 확인한 연속 두 최신 구간에 겹치는 문서가 없으면 대량 수신/재연결로 중간 기록을 놓쳤을 수 있다. 기존 과거 기록을 초기화하고 안내하며, 새 최신 구간의 커서에서 다시 이전 기록을 조회한다. 구간을 무조건 이어 붙여 중간 누락을 숨기지 않는다.
- 최신 50개의 개수가 그대로인 상태에서 새 메시지가 도착해도 마지막 메시지 ID 변화로 자동 스크롤/새 메시지 안내가 동작한다.
- 이전 기록을 누르지 않은 동안은 최근 50개만 화면 메모리에 유지한다. **이전 기록을 열면 사용자가 요청한 과거 기록과 이어지는 새 메시지는 누적된다.** 네트워크 요청/구독 개수 제한이 전체 메모리·DOM 크기의 상한을 뜻하지는 않는다. 장시간 세션의 가상 목록/표시 창 제한은 후속 작업이다.
- 실제 첫 입장 검증 중 구형 캐시의 인원 정보 때문에 즉시 퇴장 처리되는 문제를 재현했다. 서버 확인 전의 부재/종료 캐시는 무시하고, 서버가 확인한 퇴장만 세션 종료로 반영한다. 메타데이터 변경도 구독하며, 서버 권한 규칙 자체는 변경하지 않았다.

### 번들 및 운영 검사

- `MainHeader`의 프로필을 `LazyModalUserProfile`로 분리했다. 프로필 조회 중/조회 실패 시 저장을 막아 빈 닉네임으로 덮어쓰는 것을 방지한다. 지연 로딩 상태와 재시도 화면을 제공한다.
- `yarn check:bundle`: `.output/public/_nuxt`의 JS 파일 크기와 gzip 크기, 전체 합계를 출력하고 단일 파일이 500,000바이트를 넘으면 실패한다. 빌드 경고 한도를 올리지 않았다. **최대 파일 크기 감소는 초기 전송량 전체가 같은 비율로 줄었다는 뜻은 아니다.** 전체 코드에는 이번에 추가한 페이지 처리 기능도 포함된다.
- `.github/workflows/quality.yml`: PR, develop/main 푸시, 수동 실행 시 Node 24·Java 21·고정 Yarn 버전으로 설치 → 타입 검사 → 린트 → 에뮬레이터 테스트 → 빌드 → 번들 검사 → 로컬 HTTP 검사를 수행한다. 테스트용 Firebase 값만 사용하며 운영 키/배포 권한은 없다.
- `.github/workflows/production-smoke.yml`: `Production`/`production` 환경 배포 성공 이벤트 또는 수동 실행 시 main의 검사 스크립트로 고정 운영 주소만 확인한다. 이벤트가 전달한 임의 URL이나 코드를 실행하지 않는다. Actions 권한은 `contents: read`, 체크아웃 인증정보는 저장하지 않으며 공식 Actions 버전을 SHA로 고정했다.
- `yarn test:production`: 운영 공개 페이지, 테스트 경로 404, 잘못된 전적 입력 400/no-store를 검사한다. **실제 PUBG 조회·인증·팀 생성·채팅·자동 정리 API는 호출하지 않는다.** 서버 응답 본문을 실패 로그로 출력하지 않는다. 인증이 필요한 기능이나 Firestore 실시간 목록까지 검증하는 검사는 아니다.
- 운영 전적 API의 429/502/503/504는 `pubg_stats_failure` 구조화 로그에 상태 코드·처리 시간만 남긴다. 닉네임·UID·URL·API 키·SDK 예외는 기록하지 않는다. 같은 상태는 서버 인스턴스별 60초에 한 번만 출력하고 그 사이 억제한 건수를 다음 로그에 표시한다. 호출이 더 없으면 억제 건수가 출력되지 않으므로 완전한 요청 통계가 아니다.
- 워크플로는 파일을 추가한 상태이며 **원격 Actions 실행·브랜치 보호·배포 이벤트 연동은 아직 검증하지 않았다.** main에 워크플로가 반영되고 Vercel이 해당 이름의 deployment_status 이벤트를 보내야 자동 배포 검사가 실행된다. 지원하지 않는 경우 Actions의 수동 실행 또는 로컬 명령을 사용한다. 정기 모니터링·메일/Slack 알림·유료 서비스는 활성화하지 않았다.

## 검증 결과

- 최종 검사: `yarn typecheck`, `yarn lint`, `yarn test` **87개**, `yarn build`, `yarn check:bundle`, `yarn test:smoke` **13개 경로** 모두 통과했다. 최대 JS 청크는 460,828바이트로 500,000바이트 예산 이하다. `git diff --check`도 통과했다.
- 단위/에뮬레이터 테스트: 페이지 경계와 같은 시각 정렬, 빈 종료 팀 페이지, 채팅 중복 제거, 멤버 전용 권한, 이전 요청 재시도·무효화, 캐시/미확정 시각, 구간 단절, 스크롤 앵커, 고정 길이 최신 창, 첫 입장 캐시 경합, 안전한 운영 검사/로그를 포함한다.
- 브라우저: 로컬 Auth/Firestore 에뮬레이터의 팀 45개가 **20 → 20 → 5개**로 이동하고 마지막 페이지의 다음 버튼이 비활성화되는 것을 확인했다. 최신 팀 이동과 지연 로딩 프로필 열기/닉네임 표시가 정상이다.
- 채팅 120개가 **50 → 100 → 120개**로 로딩되고 문서 ID 120개가 모두 고유했다. 두 번째 페이지 로딩 전후 보이던 메시지의 상대 위치는 **-19.75px로 동일**했다. 모든 이전 기록을 읽으면 버튼이 사라진다.
- 390px 모바일 화면에서 가로 넘침 없이 입력창 하단 823px(화면 높이 844px), 추가 메시지 전송 후 121개 표시/입력 초기화, 퇴장 후 팀 목록 복귀를 확인했다. 브라우저 경고/오류 로그는 없었다.
- 모든 UI 테스트는 `demo-pubg-ui`와 Git 제외된 `.firebase/stage5-ui` 확장을 재사용했다. 운영 계정/Firestore/PUBG 키는 사용하지 않았다.
- 검증용 에뮬레이터의 팀 45개와 하위 채팅, 프로필 2개, 테스트 Auth 계정을 정리했다. 개발 서버·에뮬레이터를 종료하고 테스트 브라우저 탭과 화면 크기 재정의도 해제했다.
- `yarn audit` 재검사: High/Critical 0, Moderate 13, Low 1(의존 경로 기준). 기존 uuid/OpenTelemetry/qs/stream-json/csv-parse/esbuild 경고가 남아 있으며 의존성 버전이나 lockfile을 변경하지 않았다. 경고를 숨기는 ignore나 강제 major resolution도 추가하지 않았다.

## 배포와 남은 항목

- 이번 앱 변경은 Firebase 규칙·인덱스·환경변수·데이터 이전 없이 배포할 수 있다. 커밋·푸시·운영 배포는 별도 요청에 따른다.
- 종료 팀을 서버에서 제외하는 상태 필드/이전 설계, 서버 자동 방 정리 활성화, 실제 두 계정·휴대폰 검증, 장시간 채팅 가상 목록, 다중 인스턴스 PUBG 공유 캐시/제한, 운영 오류/사용량 알림 설정은 별도로 남는다.
- 배포 후 Actions 최초 성공 여부와 Production 이벤트 연결을 확인하고, 필요하면 저장소 관리자가 Quality checks를 필수 상태 검사로 지정한다. 권한/브랜치 보호/외부 알림은 이 작업에서 변경하지 않았다.
