# 3단계: 팀 목록 사용성 개선

## 변경 내용

- 일회성 `getDocs` 조회를 페이지 수명에 맞춘 실시간 구독으로 변경했다. 팀 추가, 인원 변경, 종료가 열린 목록에 반영된다.
- `useTeam`은 팀 생성만 담당한다. 쿼리/데이터 변환은 `services/teamList.ts`, 목록 상태와 구독 수명은 `useTeamList.ts`로 분리했다.
- 필터 변경 시 이전 구독과 목록을 정리하고 최신 조건으로 구독한다. 이전 구독의 늦은 성공/실패 콜백은 무시한다. 같은 이벤트 루프의 필터 초기화는 한 번만 조회한다.
- 로딩, 모집 팀 없음, 조건에 맞는 팀 없음, 조회 실패를 구분한다. 실패 시 다시 시도할 수 있고, 수동 갱신 중에는 마지막 목록을 보존한다.
- 캐시 결과와 서버 확인 결과를 구분한다. 오프라인 또는 조회 실패 시 마지막 목록이 최신이 아닐 수 있음을 표시한다. 캐시의 빈 결과를 실제 모집 팀 없음으로 표시하지 않는다.
- 연결 복구/탭 복귀 시 다시 구독하며 페이지를 벗어나면 구독과 이벤트 핸들러를 해제한다. SSR 단계에서는 구독하지 않는다.
- 플랫폼별 페이지 키와 허용값 검증으로 플랫폼 전환 시 상태를 초기화하고 잘못된 플랫폼은 404 처리한다.
- 필터/새로고침에 접근성 이름을 추가하고 필터 줄바꿈을 허용했다. 팀 카드는 키보드 Enter/Space로 선택할 수 있으며, 이미 참여한 회원은 정원이 차도 재입장할 수 있다. 최종 입장 권한/정원 검증은 기존 트랜잭션과 규칙이 담당한다.

## 검증

- 자동 테스트: 총 42개 통과. 새로운 10개는 응답 순서 역전, 초기 구독/해제, 캐시, 실패 재시도, 오프라인/연결 복구, 필터 쿼리, 실시간 인원/종료 반영을 검사한다.
- 타입 검사, 린트, 프로덕션 빌드, HTTP smoke 검사 12개, `git diff --check` 모두 통과했다.
- 로컬 `demo-pubg-ui` 에뮬레이터 브라우저에서 로딩/빈 목록, 실시간 팀 추가, 모드 필터와 초기화, null 티어, 읽기 권한 거절 안내와 규칙 복구 후 재시도를 확인했다.
- 운영 데이터/규칙/환경변수는 변경하지 않았다. 에뮬레이터에만 만든 UI 테스트용 팀 2개를 정리하여 남은 팀 0개를 확인했고, 검증 서버와 에뮬레이터를 종료했다.

## 배포와 남은 범위

- 이번 변경은 Firebase 규칙/인덱스/환경변수 변경이 없다. 이미 2단계 규칙이 반영된 환경에서는 앱만 배포하면 된다. 운영 배포는 사용자가 별도로 진행한다.
- 실시간 구독은 변경 문서 읽기와 재연결 시 읽기 비용을 발생시킨다. 이번 단계는 기존 필터 범위를 유지하며 목록 개수 제한/페이지 처리는 다음 성능 단계에서 다룬다. 종료된 팀 제외도 기존처럼 클라이언트에서 수행한다.
- 대형 클라이언트 번들 경고와 에뮬레이터 Admin SDK 메타데이터 조회 경고는 기존 사항이다.
- 작은 화면의 공통 헤더 메뉴에 플랫폼 링크가 나타나지 않는 기존 문제를 로컬에서 확인했다. 공통 헤더/모달/채팅방 모바일 대응 단계에서 함께 개선한다.
- 2단계 서버 자동 정리 활성화와 운영 실제 계정 검증은 여전히 별도 작업이다.
