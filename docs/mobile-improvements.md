# 5단계: 모바일 화면 개선

## 변경 범위

- `MainHeader`/`NavigationMenu`: 모바일 메뉴 본문에 스팀·카카오 링크를 추가하고 선택 후 닫는다. 데스크톱과 같은 링크 정의를 재사용하며 아이콘 버튼에 접근성 이름과 최소 44px 터치 영역을 부여했다. 작은 화면에서는 계정 상세 정보를 숨겨 헤더가 넘치지 않도록 했다.
- 팀 목록: 이중 좌우 여백을 줄이고 카드 제목·설명·인원 표기가 긴 경우 줄바꿈한다.
- 채팅방: 고정 680px 높이와 1/4·3/4 너비를 제거했다. 모바일은 접속자를 접고 펼칠 수 있는 세로 배치, 1024px 이상은 접속자 320px와 가변 채팅 영역의 좌우 배치다. 긴 제목·설명·접속자 목록은 제한된 영역에서 스크롤한다.
- 화면 높이: `VisualViewport.resize`와 창 크기 변경을 구독해 채팅방 높이를 갱신한다. 확대할 때는 레이아웃이 과도하게 줄지 않도록 창 높이를 사용하며, 미지원 환경은 창 높이로 대체한다. 페이지 해제 시 이벤트를 제거한다.
- `Chat/Panel`로 메시지 표시·입력 UI를 분리했다. 입퇴장·권한·Firestore 서비스는 기존 경로를 유지한다. 입력은 16px 글자와 안전 영역 하단 여백을 사용한다.
- 채팅 동작은 `useChatComposer`/`useChatScroll`로 분리했다. 한글 조합 Enter/Safari keyCode 229/키 반복 전송을 막고, 전송 중 중복 요청을 막는다. 실패 시 초안과 재시도 가능 상태를 보존한다. 이전 메시지를 읽는 동안 자동 스크롤하지 않고 새 메시지 이동 버튼을 표시한다.
- 긴 URL/닉네임은 가로로 넘치지 않고 줄바꿈하며, 접속자 복사·전적 버튼은 hover 없이 항상 보인다. 복사 실패는 성공으로 표시하지 않는다.
- 프로필·팀 생성·전적·확인/알림 모달은 `responsiveModalUi`를 공유한다. 본문만 스크롤하고 하단 버튼은 유지하며, 작은 화면 입력·버튼을 키웠다. 팀 생성 선택 항목은 모바일 한 열/넓은 화면 세 열이다. 전적은 넓은 화면에서 더 넓게 표시한다.

## 이전 / 이후 핵심

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| 모바일 메뉴 | 메뉴 본문 링크 없음 | 공통 링크를 세로 배치, 선택 후 닫힘 |
| 채팅 높이 | `h-[680px]` | 보이는 화면 높이에 맞춤 |
| 접속자 조작 | hover에서만 버튼 표시 | 항상 표시, 최소 44px 터치 영역 |
| 채팅 수신 | 매번 맨 아래로 이동 | 읽던 위치 유지 및 새 메시지 안내 |
| 팀 생성 선택란 | 고정 네 열에 세 항목 | 모바일 한 열 / 넓은 화면 세 열 |

```text
room/[id].vue (기존 useChat으로 입퇴장·메시지 저장)
├─ RoomMemberItem
└─ ChatPanel
   ├─ ChatMessage
   ├─ useChatComposer (입력·전송 상태)
   └─ useChatScroll (읽기 위치·최신 메시지 이동)
```

ChatPanel의 메시지 저장은 기존 `useChat.sendChatMessage`에 위임한다.

## 검증

- 새 단위 테스트 9개: IME/Enter 및 조합 확정 기본 동작 보존, 하단 판정, 읽기 위치·최신 이동·해제, 초기 메시지 위치, 중복/비활성 전송과 새 초안 보존, 실패 후 재시도, viewport 변경/확대/해제/미지원 대체.
- 전체 자동 테스트 67개, 타입 검사·린트·프로덕션 빌드·HTTP smoke 13개 및 `git diff --check` 통과. 기존 대형 청크 경고는 남아 있다.
- 로컬 `demo-pubg-ui` Auth/Firestore 에뮬레이터에서 실제 앱으로 확인했다. 운영 계정/Firestore/PUBG 키를 사용하지 않았으며 전적은 기존 테스트용 SDK 모의 응답이다. 테스트 레이어 `.firebase/stage5-ui`는 Git에서 제외되며 명시적으로 확장할 때만 적용된다.
- 320×568: 로그인 헤더, 프로필/팀 생성/경쟁전 모달, 긴 URL·닉네임, 실제 채팅 입력/전송을 확인했다. 문서 너비는 320px, 모달 너비는 288px이며 가로 넘침이 없었다. 채팅 입력창 하단은 547px로 화면 안에 있었다.
- 390×844: 메뉴의 카카오 이동·자동 닫힘과 접속자 펼치기/복사·전적 버튼을 확인했다. 복사 버튼은 44×50px였다.
- 390×400: 짧아진 화면에서 입력창 하단 379px와 가로 넘침 없음을 확인했다. 이는 높이 축소 검사이며 실제 가상 키보드 검증을 대체하지 않는다.
- 768×1024: 가로 넘침 없음, 입력창 하단 991px, 퇴장 확인·목록 복귀 확인.
- 1440×900: 접속자 320px/채팅 896px 좌우 배치, 가로 넘침 없음. 브라우저 경고/오류 로그 없음.
- 에뮬레이터에서 새 메시지 도착 후 읽기 영역 `scrollTop=0` 유지 및 새 메시지 버튼 표시, 버튼 클릭 후 최신 위치 이동을 확인했다.
- 검증 후 이번 단계가 만든 로컬 방·하위 채팅/접속 정보·공개 프로필 2개·테스트 계정 1개를 삭제했다. 방/채팅/접속 문서가 남아 있지 않음을 확인했으며 개발 서버·에뮬레이터·브라우저 탭을 종료하고 화면 크기 설정을 복구했다.

## 배포 및 남은 작업

- Firebase 규칙·인덱스·환경변수·의존성 변경 없음. 앱 배포만 필요하며 커밋·푸시·운영 배포는 별도 요청에 따른다.
- 실제 iOS Safari/Android Chrome의 가상 키보드, 한글 조합, 화면 회전, 안전 영역, 모달 중첩의 실기기 확인은 남아 있다. 데스크톱 브라우저의 화면 크기 변경과 단위 테스트만으로 실기기 동작을 확정하지 않는다.
- 6단계 목록/채팅 페이지 처리·번들 최적화·자동 검사, 서버 자동 방 정리 활성화와 운영 두 계정 테스트는 별도 범위다.

참고: [VisualViewport와 화면 키보드](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport). Nuxt UI 헤더/모달 슬롯은 설치된 `@nuxt/ui` 4.11.1 소스와 생성 테마를 기준으로 확인했다.
