# 1단계 보안 변경 적용

> 운영 반영 업데이트 (2026-09-13): 1단계 규칙과 인덱스 배포, 공개 프로필 9개 이전, 운영 전적 API 응답 및 본인 계정의 팀 생성/채팅/퇴장 확인을 완료했다. 아래의 미인증·미배포·키 미설정 설명은 최초 로컬 검증 당시 기록이다. 후속 2단계 변경과 별도 배포 순서는 [팀·채팅 안정화](./room-stability.md)를 따른다.

## 데이터와 권한

- `PROFILES/{uid}`: 기존 이름·이메일·닉네임 문서. 본인만 단건 읽기 가능하며 클라이언트 쓰기와 목록 조회는 금지한다. 기존 데이터를 삭제하거나 덮어쓰지 않는다.
- `PUBLIC_PROFILES/{uid}`: `id`, `steamNickname`, `kakaoNickname` 세 필드만 저장한다. 로그인한 사용자가 단건 조회하고 본인만 수정할 수 있다. 전체 목록 조회와 개인정보 필드 추가는 금지한다.
  관리자 도구로 잘못 넣은 추가 필드가 있는 문서도 클라이언트 읽기를 거절한다.
- Google 이름·이메일·사진은 로그인한 본인의 Firebase Auth 객체를 통해 헤더에 표시한다. 공개 프로필로 복제하지 않는다.
- `TEAMS/{id}`: 모집 메타데이터는 공개 조회한다. 생성자는 자신의 자리 하나만 등록할 수 있다. 가입·퇴장은 호출자 자신의 자리만 변경하며, 프로필 닉네임과 정원을 규칙에서도 검사한다. 다른 멤버 제거, 방 정보 변경, 생성 시각 위조는 금지한다.
- `CHAT_MESSAGES`: 현재 팀원만 읽고 쓴다. 발신 UID·닉네임·서버 시각·2000자 제한을 검사한다. 활성 방 메시지의 수정·삭제는 금지한다.
- 마지막 멤버는 방에 `closedAt`, `closedBy`를 기록하고 인원을 비운다. 이후 가입·메시지 전송은 거절된다. 마지막 멤버만 메시지를 400개씩 삭제한 뒤 방을 삭제할 수 있다. 정리 도중 연결이 끊긴 방은 닫힌 상태로 목록에서 제외된다. 만료 방의 자동 복구·서버 정리는 후속 단계다.
- 명시적으로 정의하지 않은 컬렉션은 모든 클라이언트 접근을 거절한다. `FREE_BOARD` 등 별도 기능을 운영 중이라면 실제 배포 규칙과 대조한 후 반영한다.

## 로컬 검증

Node.js 24.11 이상(24.x), Java 21 이상을 사용한다.

```sh
yarn install --frozen-lockfile
yarn lint
yarn typecheck
yarn test
yarn build
yarn test:smoke
```

`yarn test`는 `127.0.0.1:8089`의 Firestore 에뮬레이터와 `demo-` 프로젝트만 사용한다. 운영 Firebase 인증이나 데이터가 필요하지 않다. 보안 규칙의 허용·거절, 동시 가입, 종료 후 정리 권한, 개인정보 이전의 dry-run·재실행 안전성을 검사한다. Smoke 테스트는 PUBG 키를 비운 별도 로컬 서버를 실행해 `/test` 404와 API 입력 검증을 확인한다.

## 기존 닉네임 이전

로그인한 사용자는 공개 문서가 없는 경우에 한해 본인의 기존 문서에서 닉네임을 이전한다. 이미 만들어진 공개 문서는 우선하며, 타인의 기존 개인정보 문서를 읽는 fallback은 없다.

기존 방의 모든 팀원 닉네임이 즉시 보여야 하므로 운영 반영 시 관리자 이전 도구를 먼저 실행한다. 명시적인 프로젝트 ID와 해당 프로젝트를 읽고 쓸 수 있는 Application Default Credentials가 필요하다. 서비스 계정 JSON이나 토큰을 저장소에 추가하지 않는다.

```sh
# 기본 동작은 읽기 전용. 대상 수만 출력하며 개인정보는 출력하지 않는다.
yarn migrate:profiles --project YOUR_PROJECT_ID

# dry-run 결과를 확인한 후 누락된 공개 문서만 생성한다.
yarn migrate:profiles --project YOUR_PROJECT_ID --apply
```

이전은 200개 단위로 순회한다. 문서 ID를 UID로 사용하고 허용된 닉네임 필드만 복사한다. 기존 공개 문서는 트랜잭션으로 확인하여 덮어쓰지 않는다. 64자를 초과하는 닉네임은 건너뛰고 `invalid` 건수 및 실패 종료 코드를 반환하므로 수동 확인 후 재실행한다. 원본 `PROFILES`는 보존한다.

## 운영 반영 순서

현재 운영 규칙은 저장소에 없었으며, 로컬 Firebase CLI 로그인/관리자 인증도 제공되지 않았다. 이 변경은 운영 규칙을 조회하거나 배포한 결과가 아니다.

1. Firebase 콘솔의 기존 규칙을 백업하고, 이 저장소 이외의 앱이나 컬렉션이 같은 프로젝트를 쓰는지 확인한다.
2. 기존 규칙과 데이터가 확인된 유지보수 시간에 새 규칙과 인덱스를 배포한다.
3. 관리자 이전 도구의 dry-run을 확인하고 `--apply`로 공개 닉네임을 이전한다.
4. 새 앱을 배포하고 기존 접속자의 새로고침을 안내한다. 기존 앱은 `PROFILES` 조회와 클라이언트 시각 쓰기를 사용하므로 새 규칙과 호환되지 않는다.
5. 서로 다른 두 계정으로 팀 생성·가입·채팅·마지막 퇴장을 확인하고, 비회원과 제3자 계정의 채팅 접근 거절을 확인한다.

```sh
yarn firebase deploy --only firestore:rules,firestore:indexes --project YOUR_PROJECT_ID
```

새 앱만 배포하면 기존 DB 규칙의 개인정보 노출 가능성이 남는다. 규칙만 배포하면 이전 앱의 일부 기능이 거절되므로 위 순서를 함께 수행해야 한다. 문제 발생 시 공개 접근을 다시 허용하는 규칙으로 되돌리지 말고 유지보수 상태에서 원인을 해결한다.

## 전적 API 설정

`PUBG_API_KEY`는 빌드 환경에, 빌드 후 런타임에서 주입하는 경우 `NUXT_PUBG_API_KEY`에 설정한다. 둘 다 서버 전용이다. 키가 없으면 503, 잘못된 플랫폼/닉네임 입력이면 400으로 응답한다. 실제 전적의 랭크·일반 통계 분리 및 캐시는 3단계 범위다.

## 검증 결과 (2026-09-13)

- Nuxt 4.5.2, Nuxt DevTools 3.4.2, Firebase 12.19.0으로 업데이트했다. 실제 사용하지 않던 Maps, Pinia, Nuxt Scripts, VueUse 직접 의존성/모듈을 제거했다.
- `yarn lint`, `yarn typecheck`, `yarn test` (17개), `yarn build`, `yarn test:smoke` (10개 응답 검사)가 통과했다. 브라우저에서도 홈과 팀 목록 렌더링을 확인했다.
- 전체 잠금 파일의 `yarn audit` 결과는 Critical 0, High 0, Moderate 13, Low 1이다. 경로별 중복 집계가 포함되어 있다.
- 남은 Moderate 항목은 Firebase 관리·이전·에뮬레이터 도구의 `uuid`, `@opentelemetry/core`, `qs`, `stream-json`, `csv-parse` 경로다. Low 항목은 Nuxt UI의 폰트 빌드 도구가 사용하는 `esbuild` 경로다. 취약점 검출을 숨기는 ignore 설정이나 호환성을 검증하지 않은 강제 major-version resolution은 추가하지 않았다. 상위 도구의 업데이트를 추적하고, 관리 도구에 신뢰할 수 없는 입력을 전달하지 않는다.
- 빌드에는 500kB를 넘는 클라이언트 청크 경고가 남아 있다. 번들 분리는 후속 성능 개선 범위다.
- 운영 규칙 배포, 운영 데이터 이전, 실제 Google 로그인과 두 계정의 종단간 검증은 수행하지 않았다. 로컬 `.env`에 PUBG 키가 없어 실제 PUBG API 성공 응답도 미검증이다. Smoke 테스트는 외부 API 호출 없이 입력 거절과 미설정 응답을 검증한다.
